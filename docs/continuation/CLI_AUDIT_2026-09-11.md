# CLI audit — September 11, 2026

This pass reviewed the public CLI, provider/runtime boundaries, local command execution, checkpoint and session persistence, MCP lifecycle, terminal startup, Rust state service, and package tooling. It combined source inspection with the complete TypeScript suite, Rust tests, and targeted reproductions. It is a broad engineering audit, not a claim that every path has been exhaustively reviewed. Private services and live paid provider calls were outside this pass.

## Fixed

| Problem | Result | Evidence |
| --- | --- | --- |
| Shell expansions were silently bypassed by direct argv execution. `printf "%s" "$PWD"` printed the literal variable; globs, leading assignments and newline-separated commands were also mishandled. | Route shell expressions through the shell, retain literal quoted arguments, and preserve POSIX backslashes inside double quotes. Recheck cancellation after the containment probe. | `packages/core/src/cli/command.test.ts`: actual subprocess regressions for expansion, globbing, assignments, multiline commands and quoting. |
| A process killed by a signal could return exit code zero. | Signal exits return a nonzero status, including 143 for SIGTERM. Git checkpoint subprocesses also no longer treat missing exit codes as success. | Real self-terminating child process regression. |
| `/diff` omitted newly created files. | Stage a comparison snapshot in a unique temporary private index; compare it against the checkpoint. The user's index remains unchanged and `.archymedes` stays excluded. | Real Git repository regression verifies added content, stats, preserved index and successful undo. |
| An MCP server could deadlock after filling its unread stderr pipe. | Drain diagnostic output without mixing it into the protocol. | A fixture writes 2 MiB of diagnostics before answering a tool request. It previously timed out and now succeeds. |
| Calls after MCP closure could write to a dead pipe or return cached tools for a dead connection. | Preserve the connection's terminal error, reject later calls immediately, handle stdin errors, and wait for stdout to drain before processing process closure. | Close-then-call and close-then-list regressions. |
| Valid JSON with an invalid queue envelope was treated as an empty job queue. A later mutation could overwrite it. | Reject malformed queue envelopes; retain the existing file. | List and enqueue both reject `{"jobs":"invalid"}` and preserve its exact bytes. |
| Startup animation could redraw after keyboard input. | Stop rotation on input, skip it when text is already pending, and remove the temporary input listener on completion. | Animation cancellation regression alongside resize, ASCII and layout checks. |
| The Rust lockfile still named the root package `nova-state`. | Lockfile now matches the manifest's `archymedes-state` package, without changing dependency versions. | Rust tests and locked offline Cargo metadata validation. |
| Two independent writers to the same session could corrupt its event journal, since ownership was never established before a turn wrote to it. | New `packages/core/src/cli/file-ownership.ts`: an agent must acquire session ownership (an age/liveness-aware lock, reclaimable from a dead writer) before any model call, tool effect, undo, or session mutation. A second concurrent writer is rejected outright; each agent instance also gets its own checkpoint index path instead of a path shared across agents in the same project. | `file-ownership.test.ts`; `agent.test.ts`'s `acquireOwnership`/resume coverage. |
| Interrupted hosted (paid) requests had no durable recovery: a client crash between provider settlement and the session snapshot save could leave paid work unrecoverable, or risk a duplicate charge on retry. | New `packages/core/src/cli/hosted-recovery.ts`: requests are persisted (mode 0600, integrity-checked, atomic rename) before dispatch and responses before returning to the runtime. On resume, `ArchymedesAgent.recoverPending()` reconciles pending entries through a dedicated recovery-only path — `AgentTurnProvider.recoverComplete`/`recoveryScope` for providers (like the hosted cloud provider) that must never create a new reservation or provider call during recovery, falling back to the ordinary `complete` for providers with no such distinction. The private hosted service gained a matching `POST /v1/chat/completions/recover` route and `AccountLedger.recoverCompletion` lookup that only reads a stored outcome by idempotency key and payload fingerprint — it never starts or replays provider work itself. Recovered tool calls are never replayed; the transcript is annotated that their outcome is unknown. | `hosted-recovery.test.ts`, including a real end-to-end fixture: an HTTP server, a child process `SIGKILL`ed right after settlement, and a resumed session that recovers the paid answer with exactly one provider invocation and one charge. `agent.test.ts` recovery coverage. In `.private/archymedes-cloud`: `recoverCompletion` ledger coverage in `test-worker/ledger.test.ts` (real Durable Object) and the `/recover` HTTP contract in `test/completion.test.ts` (missing/processing/failed/fingerprint-mismatch/completed). |

The existing containment test used JavaScript backticks inside shell double quotes. Correct shell expansion exposed that fixture error; the test now executes a script file so its intended detached-child behavior is unambiguous.

## Remaining priorities

### P2: stronger persisted-record validation and lock recovery

Queue envelopes now fail closed, but individual job records still enter through a type assertion. Session loading similarly validates only part of the transcript shape. Session and job locks use age-based stale-lock deletion; elapsed time alone does not establish that a writer is dead.

Next change: versioned record validation and ownership-aware lock recovery, with corrupt-record and slow-writer fixtures. Preserve damaged files and distinguish corruption from an empty history or queue.

### P2: reduce orchestration coupling

The terminal entrypoint remains approximately 5,000 lines and combines configuration, command dispatch, rendering, approvals and lifecycle management. Extract coherent handlers as they change, retaining real PTY coverage. Avoid a broad rewrite that obscures behavioral regressions.

## Validation boundaries

The initial sandbox run failed because local listeners and subprocess behavior were restricted. The unrestricted baseline passed all 175 test files: 2,852 tests passed and one was skipped. Those sandbox failures were not treated as product regressions.

Final validation, after the concurrent-ownership and hosted-recovery work above landed:

- `bun run check` (main repo): 177 test files passed; 2,867 tests passed and one skipped; typecheck and package build passed.
- `bun run test:state`: 29 Rust tests passed (7 library, 2 binary, 20 integration); offline `cargo metadata --locked` also passed with the corrected lockfile.
- `bun run verify:package`: `archymedes-cli-2.0.0.tgz`, 27 entries; isolated installation, Node startup, provider listing and terminal dependency imports passed.
- `bun run check` in `.private/archymedes-cloud/infra/cloudflare`: typecheck, 36 mocked-boundary HTTP tests, 9 real-Durable-Object worker tests, and the Go router tests all passed — including the new `recoverCompletion` ledger coverage and the `/v1/chat/completions/recover` HTTP contract.
- `git diff --check`: passed.

The hosted-recovery fix went through one iteration: the first pass's `dispatch()` unconditionally required `provider.recoverComplete` for recovery-only calls, which failed 3 of the new `hosted-recovery.test.ts` cases (fixtures whose fake providers only implement `complete`). Fixed by falling back to `complete` whenever a provider declares no dedicated recovery-only entry point — that entry point exists only to stop a provider that can create new work from doing so during recovery, so a provider with no such distinction has nothing extra to protect.

Tests use local fixtures; no live provider billing, production deployment or publication was performed. Linux subprocess and PTY checks do not prove native Windows or macOS behavior.
